# Главная v2

Изолированный каталог и универсальная страница статьи. Текущие статьи остаются в `src/views`, новая реализация — в `src/v2`.

Перенесены все 123 статьи из 14 тем старой главной, кроме AI-ассистированной разработки. Дополнительно есть новая статья `llm-introduction` в разделе «Основы ИИ и локальное использование» и демонстрационная статья `block-showcase`. Полнота переноса и порядок исходных разделов проверяются по `AllQuestionPage.vue`; динамический AI-раздел явно исключён из этой проверки. Новые материалы v2 учитываются отдельно и не требуют `legacyPath`.

## Как добавить статью

1. Добавить метаданные в `mocks/catalog.ts`: `id`, `categoryId`, название, описание и теги. При необходимости добавить категорию и `legacyPath` для сравнения со старой страницей.
2. Создать `mocks/articles/<id>.ts` с `schemaVersion: 1`, метаданными и массивом `sections`. Каждый раздел содержит `id`, `title`, `blocks`.
3. Использовать `satisfies Article` из `types/article.ts`. Новые файлы подхватываются автоматически через ленивый `import.meta.glob`; маршруты для каждой статьи добавлять не нужно.

Идентификаторы используют строчные латинские буквы, цифры и дефисы. В каждом массиве идентификаторы должны быть уникальны. Порядок массивов определяет порядок отображения. Каталог содержит только метаданные; полные статьи загружаются при открытии.

Для вводного содержимого перед первым разделом используется необязательный массив `intro`. При его наличии описание из каталога не выводится в статье повторно. Это позволяет сохранить исходное вступление с выделениями и таблицами, не добавляя заголовок «Введение».

Основной `title` остаётся обычным текстом для каталога. Если заголовок самой статьи содержит inline code или выделения, можно дополнительно передать `titleMarkdown`: его отображает общий `ArticleTitle`, используя безопасный inline Markdown.

Текстовые блоки принимают Markdown: абзацы, списки, выделения, ссылки, inline code и цитаты. Заголовки разделов и примеры кода задаются отдельными блоками; произвольный HTML экранируется. Большие примеры можно хранить в `mocks/snippets/*.txt` и импортировать через `?raw`, как в HTML-статье. Такие примеры не компилируются как исходники приложения.

`cards`, `accordion`, `tabs`, `steps` и `timeline` содержат элементы `{ id, title, blocks }`. `callout` принимает вложенные `blocks`. Ячейки таблиц — массивы блоков; количество ячеек каждой строки должно совпадать с количеством колонок. Это позволяет использовать списки и примеры кода внутри таблиц и ответов.

У таблицы без шапки все `columns` содержат только `id`, без `label`. Смешивать колонки с подписями и без подписей нельзя. Для отдельных подзаголовков предусмотрен `heading` с `level: 3 | 4` и `text`; для меток — `tags` с массивом строк `items`. Карточки поддерживают от одной до четырёх колонок, а элементы карточек — `headingLevel: 3 | 4` (по умолчанию 3).

У карточек `title` необязателен: содержимое без заголовка передаётся через `blocks`. Подпись внутри предупреждения можно передать как `callout.label` — она не становится заголовком документа. Заголовки вопросов в `accordion` поддерживают inline Markdown, включая выделения и код.

У `timeline` заголовок элемента тоже необязателен. `steps.showTitle: false` убирает повторный заголовок, если в содержимом шага уже есть свой. Для списка с вложенными примерами кода используется `list`: `ordered` и элементы `{ id, blocks }`. Блок `inline-code` хранит `lines` — сегменты кода, разделённые явными переносами; `line-break` сохраняет отдельный перенос строки. Обычные списки и короткий inline code по-прежнему удобнее заполнять Markdown.

`steps.mode: 'sequence'` показывает статическую последовательность этапов без переключателей. `steps.restartLabel` добавляет на последнем шаге кнопку возврата к первому с указанной подписью. `progress` принимает `value` от 0 до 100, подпись `label` с inline Markdown и необязательный `tone`. В тексте разрешены точные маркеры `<u>…</u>` для подчёркивания и `<kbd>…</kbd>` для сочетаний клавиш; остальные HTML-теги и атрибуты экранируются.

## Подключение бэкенда

Без настройки `articlesApi` асинхронно возвращает локальные моки. Чтобы переключить источник, задать в `.env.local` и перезапустить Vite:

```dotenv
VITE_ARTICLES_API_URL=/api/v2
```

Контракт HTTP:

- `GET /api/v2/catalog` → `ArticleCatalog`.
- `GET /api/v2/articles/:id` → `Article` с соответствующим `id`.
- Неизвестная статья → HTTP 404.

Типы ответов определены в `types/article.ts`; runtime-проверка находится в `types/article.schema.ts`. Объекты сериализуются в JSON: Vue-компоненты, функции, классы CSS и результаты Prism в ответ не входят. При некорректном ответе, неподдерживаемой версии или ошибке сети страница показывает ошибку с возможностью повторить загрузку. HTTP-источник не подменяет ошибки моками.

Страницы вызывают `api/articles.ts`; визуальное дерево собирает `components/ArticleRenderer.vue`. Запросы отменяются при смене статьи, поэтому старый ответ не заменяет новую страницу.

Реестр виджетов находится в `components/widgets/ArticleWidget.vue`: `css-specificity`, `css-units`, `testing-pyramid`. Первые два используют существующие самостоятельные тренажёры без изменения их реализации. Новый вид блока или виджета требует поддержки на фронтенде и в проверке формата.
